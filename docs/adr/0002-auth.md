# ADR 0002 — Authentication with Better Auth

Date: 2026-09-09 · Status: accepted

## Context

Every project built from the template needs email + password sign-up with verified emails,
7-day sessions, roles, and admin operations (change role, revoke sessions), served by the Hono API
and consumed by the Next.js app on another origin.

## Decision

- `better-auth` 1.7.3 with `prismaAdapter` (Prisma 7 client), `emailAndPassword`
  (`requireEmailVerification: true`), `emailVerification.sendOnSignUp`, session `expiresIn` 7d /
  `updateAge` 1d, the **admin plugin** (roles `admin | member`, `defaultRole: member`,
  `adminRoles: ["admin"]`). Extra profile fields are added through `user.additionalFields`.
  Configured once in `packages/auth` (`createAuth(options)`), instantiated by `apps/api`, mounted
  at `/api/auth/*`.
- **Schema**: Better Auth's `user / session / account / verification` models generated with
  `npx auth generate` and merged into `packages/database/prisma/schema/auth/*.prisma` with the repo
  conventions — snake_case tables (`users`, `sessions`, `accounts`, `verifications`), UUID v7
  primary keys generated by Postgres (`advanced.database.generateId: false`), plus `deleted_at`
  for soft delete. Migration `0001_init`.
- **Role column**: `role String? @default("member")`. Better Auth stores roles as strings; the
  allowed set is `roleSchema` in `@repo/validation`, not a Prisma enum, so both sides agree.
- **Verification mail** is never sent inline: `sendVerificationEmail` is a callback the API
  implements with the outbox (ADR 0004).
- **Cookies / CORS**: dev uses `localhost:3000` → `localhost:4000` (cookies are host-scoped, not
  port-scoped, so they are shared). Production deploys web and api under one parent domain and
  sets `cookieDomain` (`advanced.crossSubDomainCookies`), `trustedOrigins` = the web origin, CORS
  with `credentials: true` on `/api/auth/*` and `/trpc/*`.
- **Rate limit**: `rate-limiter-flexible` (`RateLimiterRedis`) on `/api/auth/sign-in/*`.

## Alternatives

Roll our own sessions (more code, same security burden); Clerk/Supabase (data must stay in our
database, see ADR 0001); Prisma enum for `role` (Better Auth writes strings, would break the admin
plugin's `setRole`).

## Consequences

Auth tables follow Better Auth's field names (only table/column names are mapped). Upgrading
Better Auth means re-running `npx auth generate` and diffing against the schema. Session lookup
happens per request in `apps/api/src/core/context.ts`; the web app only forwards cookies.

## Changes

- **2026-10-05** — Public sign-up is disabled (`emailAndPassword.disableSignUp: true`;
  `POST /api/auth/sign-up/email` answers 400 `EMAIL_PASSWORD_SIGN_UP_DISABLED`). Users are created
  only through the admin plugin's `auth.api.createUser`: called server-side it needs no session,
  over HTTP it needs an admin role, and it rejects a role outside the `roles` map. The web app lost
  `/register` and `register-form`, and `signUpSchema` left `@repo/validation`. Verification is
  unchanged: `createUser` sends no mail, `/send-verification-email` (resend) and `verifyEmail` still
  work; `sendOnSignUp` is now inert but harmless. In practice users come from the seed accounts
  or from an admin session calling `POST /api/auth/admin/create-user`
  (`authClient.admin.createUser`) until a create-user UI exists.
- **2026-10-05** — The role set is the catalog's `super_admin | admin | manager | staff`: the
  admin plugin runs with `defaultRole: "staff"` and `adminRoles: ["super_admin", "admin"]`
  (`ADMIN_ROLES`), `ROLES` in `@repo/validation` and the `roles` map in
  `@repo/auth/access-control` list the same four keys, and `member` is gone. `users.role` becomes
  `String @default("staff")` NOT NULL with the foreign key `users.role → roles.key`
  (`onDelete: Restrict`, indexed; migration `20261005143913_align_users_role_with_roles`, which also
  backfills existing `member` rows to `staff`), so the database refuses a role outside the
  catalog and `toAuthUser`'s fallback to `DEFAULT_ROLE` guards only the session's type. Still a
  string, not a Prisma enum, for the reason above. ADR 0005 explains why the foreign key is now
  safe and how the migration seeds the four rows.
