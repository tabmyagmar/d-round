# shadcn/ui in the monorepo

## Purpose

`packages/ui` is the single component library: shadcn primitives generated by the CLI, our form
fields and composed components on top, and the Tailwind v4 theme. This skill is the entry point for
every shadcn task. The upstream shadcn skill's convention files are vendored under `rules/` and
`customization.md` (see Upstream conventions). Project rules: `.claude/rules/ui.md`, auto-loaded for
`packages/ui/**` and `apps/web/**`.

## Project facts

| Fact           | Value                                                                                                                                                                                                                                              |
| -------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| CLI version    | `shadcn@4.21.0`, pinned in `packages/ui/package.json`. Always `npx shadcn@4.21.0 ...`, never `@latest`.                                                                                                                                            |
| Run from       | `apps/web`: its `components.json` points `ui`, `hooks` and `utils` at `@repo/ui` and css at `../../packages/ui/src/styles/globals.css` (aliases: `.claude/rules/ui.md`). The repo root answers `monorepo_root`; from elsewhere pass `-c apps/web`. |
| Output         | `packages/ui/src/components/<component>.tsx`, imported as `@repo/ui/components/<component>`.                                                                                                                                                       |
| Primitives     | Base UI (`@base-ui/react`), not Radix: `render` instead of `asChild`, `Select` takes `items`. See `rules/base-vs-radix.md`.                                                                                                                        |
| Style, icons   | `base-nova`, `lucide-react`, Tailwind v4 (no `tailwind.config`).                                                                                                                                                                                   |
| `cn()`         | `@repo/ui/lib/utils` re-exports the `cn` package; generated files import `from "cn"`.                                                                                                                                                              |
| Toast          | `import { toast } from "sonner"` (as in `apps/web/features/users/components/profile-form.tsx`), not the upstream `toast` component.                                                                                                                |
| Installed list | `cd apps/web && npx shadcn@4.21.0 info` (`--json` for scripts). No hand-maintained list anywhere.                                                                                                                                                  |

## Adding a primitive

1. `cd apps/web && npx shadcn@4.21.0 add <component>` (`dialog`, `tooltip`, `pagination`, ...). Run
   `info` first so you do not re-add an installed one.
2. Read the generated file: imports, missing sub-components, `rules/composition.md`. The relaxed
   lint rules in `packages/ui/eslint.config.mjs` apply to `src/components/*.tsx` only, so generated
   code passes as is; run `yarn prettier --write` on it (the CLI emits no semicolons).
3. If `exactOptionalPropertyTypes` complains, fix it with the smallest change and record it under
   "Known local patches" in `.claude/rules/ui.md`.
4. `yarn lint`, then import: `import { Button } from "@repo/ui/components/button"`. Run
   `yarn verify` before declaring the step done.

`tooltip` needs a `TooltipProvider` above its consumers (`apps/web/app/layout.tsx` provides it
app-wide). `calendar` pulled `react-day-picker` into `packages/ui` (no `date-fns`).

## Updating components

Smart merge, never a raw download from GitHub:

1. `npx shadcn@4.21.0 add <component> --dry-run` lists the files that would change.
2. `npx shadcn@4.21.0 add <component> --diff <file>` shows upstream against local.
3. No local changes: overwrite. Local changes (the `sonner.tsx` and `calendar.tsx` patches in
   `.claude/rules/ui.md`): apply the upstream edits by hand, or `--overwrite` and re-apply the
   patch.
4. `--overwrite` only with the user's explicit approval.
5. `yarn verify`.

Bumping the CLI is a dependency change, so agree it with the user first: change the pin in
`packages/ui/package.json`, then smart-merge each installed component.

## Adding a form field

Fields live in `packages/ui/src/components/form/` (`@repo/ui/components/form`) and bind the shadcn
`Field` primitives to react-hook-form. The catalogue, shared props and zod mapping are in
`.claude/rules/ui.md` (Forms). New field: `<name>-field.tsx` built on `useFormField` and
`FormFieldShell` (`FormFieldLabel asLegend` for grouped controls), exported with its props type from
`index.ts`, house style throughout. Raw `FieldGroup` / `Field` markup (`rules/forms.md`) belongs in
this folder and in rare non-standard controls; `apps/web` forms use the bound fields. Domain pickers
(a user picker over `trpc.user.list`) stay in `apps/web/features/`.

Example, `apps/web/features/auth/login-form.tsx`:

```tsx
<FieldGroup>
  <TextField control={form.control} name="email" label="Email" type="email" autoComplete="email" />
  <PasswordField
    control={form.control}
    name="password"
    label="Password"
    autoComplete="current-password"
  />
</FieldGroup>
```

## Creating a composed component

1. Start in the feature that needs it (`apps/web/features/<feature>/`). When it is domain-free and
   reusable across apps, move it to `packages/ui/src/components/composed/<name>.tsx`.
2. Compose primitives and `cva` variants; no data fetching, no app imports, no server-only packages
   (`boundaries/dependencies` enforces this).
3. Named export, imported as `@repo/ui/components/composed/<name>`. Existing: `DataTable`,
   `ConfirmDialog`, `StatusBadge` (`.claude/rules/ui.md`, Composed components).

Pattern, `packages/ui/src/components/composed/status-badge.tsx`:

```tsx
const statusBadgeVariants = cva("gap-1.5 font-medium", {
  variants: {
    tone: {
      neutral: "bg-muted text-muted-foreground",
      info: "bg-sky-100 text-sky-900 dark:bg-sky-950 dark:text-sky-200",
      success: "bg-emerald-100 text-emerald-900 dark:bg-emerald-950 dark:text-emerald-200",
      warning: "bg-amber-100 text-amber-900 dark:bg-amber-950 dark:text-amber-200",
      danger: "bg-destructive/10 text-destructive",
    },
  },
  defaultVariants: { tone: "neutral" },
});

export type StatusTone = NonNullable<VariantProps<typeof statusBadgeVariants>["tone"]>;

export const StatusBadge = ({
  tone,
  dot = true,
  className,
  children,
  ...props
}: StatusBadgeProps) => (
  <Badge variant="outline" className={cn(statusBadgeVariants({ tone }), className)} {...props}>
    {dot ? <span aria-hidden className="size-1.5 rounded-full bg-current" /> : null}
    {children}
  </Badge>
);
```

Domain code maps its states to a tone (`apps/web/features/users/components/role-badge.tsx`:
`admin → danger`, `member → neutral`); an outbox badge would map `PENDING → warning`,
`SENT → success`, `FAILED → danger`.

## Changing the theme

Tokens are CSS variables in `packages/ui/src/styles/globals.css`, read by Tailwind v4's `@theme`
block. Change a value there once; components use semantic classes (`bg-primary`,
`text-muted-foreground`), never raw colours or manual `dark:` overrides. `apps/web` imports the
sheet as `@repo/ui/globals.css`; `prettier-plugin-tailwindcss` sorts classes from the same file.
Custom colours, radius, dark mode, extending components: `customization.md`.

## Upstream conventions (vendored)

Copied from the `shadcn-ui/ui` repository, `skills/shadcn/` (2026-10-05), formatted with the repo's
Prettier, otherwise unchanged. Read the file that matches the task. Where a file disagrees with this
skill or `.claude/rules/ui.md`, the project wins.

| File                     | Covers                                                                                                                                             | Project deviation                             |
| ------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------- |
| `rules/styling.md`       | semantic colours, variants, `className` for layout, `gap-*` not `space-*`, `size-*`, `truncate`, `cn()`, no manual `z-index`                       | none                                          |
| `rules/composition.md`   | items inside their group, Dialog / Sheet need a Title, full Card composition, Button loading via `Spinner`, `Empty`, `Alert`, `Separator`, `Badge` | toast: `sonner`, not the `toast` component    |
| `rules/forms.md`         | `FieldGroup` + `Field`, `InputGroup`, `ToggleGroup`, `FieldSet`, `data-invalid` / `aria-invalid`                                                   | `apps/web` forms use the bound fields (above) |
| `rules/icons.md`         | `data-icon="inline-start"` / `"inline-end"`, no size classes on icons, icons passed as objects                                                     | none                                          |
| `rules/base-vs-radix.md` | `render` vs `asChild`, Select `items`, ToggleGroup, Slider, Accordion                                                                              | this project is `base`                        |
| `rules/chat.md`          | `MessageScroller`, `Message`, `Bubble`, `Attachment`, `Marker`                                                                                     | not installed; add via the CLI first          |
| `customization.md`       | CSS variables, dark mode, custom colours, radius, extending components, checking for updates                                                       | none                                          |

Every `npx shadcn@latest` in those files means `npx shadcn@4.21.0` run from `apps/web`.

Refresh: `yarn dlx skills add shadcn/ui`, copy `.agents/skills/shadcn/rules/` and `customization.md`
over these files, `yarn prettier --write` them, then remove `.agents/`, `skills-lock.json` and the
`.claude/skills/shadcn` symlink again. The upstream skill is not kept installed: it runs
`npx shadcn@latest info` from the repo root on every load (fails with `monorepo_root` here), ignores
the version pin, and its description overlaps this skill's.

## Gotchas

- Run the CLI from `apps/web`; the repo root is a monorepo root (`-c apps/web` otherwise).
  `packages/ui/components.json` (from `init --monorepo`) carries the same aliases, so keep the two
  files in sync when changing one.
- Do not hand-edit generated primitives beyond documented variant changes; regenerate instead
  (Updating components) and re-apply the known patches.
- `packages/ui` stays browser-safe: no `@repo/database`, `@repo/queue`, `@repo/logger`.
- Merge classes with `cn()`; never concatenate className strings.
- `"use client"` belongs in the component that owns interactivity, not in every file.
